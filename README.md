# 光影相框 · 使用说明

一个单文件的批量相框工具。把照片拖进去，选个版式，一次导出全部。

自动读取相机、镜头、光圈、快门、ISO、焦距、日期，排进画面；也支持全部手写。
不用装任何东西，不用联网，双击 HTML 就能跑。

```
光影相框.html          当前版本（8 种版式）
光影相框_v1_备份.html   早期快照（7 种版式，无「光影」）
```

---

## 一、快速开始

1. 双击 `光影相框.html`，用浏览器打开（Chrome / Edge / Safari 均可）
2. 把照片拖进窗口（JPG / PNG / WebP / RAW 都行），或点右上角「＋ 添加照片」
3. 左侧选版式、调参数，右侧实时预览
4. 点「导出 N 张」，得到一个 zip

拖进去多少张就处理多少张，参数是全局的，一次套用。

## 二、界面导览

```
┌──────────────────────────────────────────────────────┐
│ 光影相框                    3 张照片  ＋添加  导出 3 张 │
├────────────┬─────────────────────────────────────────┤
│  版式       │  ┌────────┐  ┌────────┐  ┌────────┐    │
│  ▣ ▣ ▣     │  │ 预览图  │  │ 预览图  │  │ 预览图  │    │
│  ▣ ▣ ▣     │  └────────┘  └────────┘  └────────┘    │
│  ▣ ▣       │   IMG_001.jpg  IMG_002.jpg  ...         │
│            │   相机·参数     相机·参数                  │
│  参数面板   │   [单图标题]    [单图标题]                │
└────────────┴─────────────────────────────────────────┘
```

- **左侧**：所有参数，改完立刻重绘，无需点确认
- **右侧**：每张照片一张卡片，左上角勾选框决定是否导出，下方输入框可给单张图改标题
- **右上角 ×**：移除这一张（鼠标移上去才出现）
- **点击预览图**：打开大图查看。大图底部有工具条：`‹` `›` 翻页、**导出这张**、**删除**
- **顶部「清空」**：一次清掉所有照片（样式参数会保留）

### 参数面板的分区顺序

按「先定颜色、再定边框」的顺序排，避免两类设置互相打断：

| 顺序 | 分区 | 管什么 |
|---|---|---|
| 1 | **调色** | 15 个预设 + 强度 + 17 根微调滑杆（默认展开） |
| 2 | **版式** | 选哪一种相框 |
| 3 | **版式参数** | 边距、字号、圆角、投影 |
| 4 | **边缘模糊** | 仅柔焦版式出现 |
| 5 | **底部文字** | 仅柔焦 / 光影版式出现 |
| 6 | **画幅** | 比例、输出长边、格式、画质 |
| 7 | **配色** | 卡纸底色、文字色、点缀色 |
| 8 | **文字** | 标题、信息模板、署名 |
| 9 | **我的预设** | 保存 / 导出 / 导入整套参数 |
| 10 | **快捷键** | 只读参考 |

第 4、5 项是条件出现的，切到对应版式才展开，所以平时看到的是一份连续的分区列表。

**关于面板长度**：微调默认是展开的，17 根滑杆让侧栏总高约 3200px，一屏看不完。
两个配套处理：分组标题（调色 / 版式 / 配色 …）会**吸顶**，滚动时始终知道自己在哪一段；
不想看滑杆时点「微调」右侧的**收起**，整段折起来只占一行。

### 快捷键

| 键 | 作用 |
|---|---|
| `1` – `8` | 直接切到第 N 种版式 |
| `←` `→` | 上一个 / 下一个版式 |
| `Ctrl / ⌘ + O` | 添加照片 |
| `Ctrl / ⌘ + E` | 导出全部 |
| `Ctrl / ⌘ + S` | 保存当前样式 |
| `Esc` | 关闭大图 |

大图打开时，`←` `→` 变成翻页，`Delete` 删除当前这张。

在输入框里打字时数字键不会触发切版式，可以放心输入。

## 三、八种版式

| 版式 | 观感 | 适合 |
|---|---|---|
| **胶片** | 米色卡纸、左对齐信息、带颗粒感 | 日常记录、旅行、人文 |
| **拍立得** | 暖白、居中、底部大留白 | 单张精选、礼物、手账 |
| **留白** | 纯白、极简、居中、宽边距 | 作品集、展览、电商 |
| **银幕** | 近黑底、左侧竖条、宽画幅感 | 电影感、夜景、氛围图 |
| **杂志** | 灰米色、衬线字、顶部细线 | 编辑风、人像、专题 |
| **悬浮条** | 照片满幅，信息压在底部 | 手机壁纸、社交平台 |
| **柔焦** | 主体清晰、边缘融入虚化背景 | 情绪片、静物、浅景深 |
| **光影** | 深色底、底部居中水印（圆点+品牌） | 品牌署名、作品打标 |

### 两个「特殊」版式

**柔焦** 和 **光影** 的文字逻辑与其余六个不同，值得单独说明：

- 其余六个版式用「**信息模板**」——可以写多行，用 `|` 分隔
- 柔焦 / 光影 用「**底部文字**」——固定两行 + 署名，样式与排版统一

这样设计是因为这两个版式的文字是「水印」性质，需要紧凑、居中、有品牌感，而不是信息罗列。

## 四、参数详解

### 4.1 版式参数（所有版式通用）

| 参数 | 范围 | 说明 |
|---|---|---|
| **边距** | 1% – 14% | 相对画面短边的百分比。越大越像卡纸装裱 |
| **字号** | 1% – 4% | 所有文字的整体缩放。光影/柔焦下是相对基准值的倍率 |
| **圆角** | 0% – 3% | 照片四角的圆角半径 |
| **投影** | 开 / 关 | 照片下方的投影 |

> 颗粒原本也在这里（一个勾选框），现在已经挪到「调色 → 质感」变成可调强度的滑杆，见 4.6。

切换版式时会自动套用该版式的默认配色、边距和字号，但**圆角、模糊强度、底图亮度、底图饱和度**会重置为该版式的默认值——避免上一个版式的参数串过来。

**文字放不下时**：字号不是硬约束。标题太长、信息行太多、字号拉到 4% 时，工具会先按比例缩字，缩到下限还放不下就从**最后一行**开始丢弃信息行——保证文字永远不出画布。想精确控制行数，就把信息模板里的行减少。

### 4.2 调色

15 个预设，点一下套用到全部照片。只改照片像素，卡纸底色、文字、点缀色都不受影响。
分成两组：前 7 个**按拍摄场景**取名字（拍什么选什么），后 7 个**按画面风格**取名字
（想要什么味道选什么）。

**按场景**

| 预设 | 观感 | 适合 |
|---|---|---|
| **原图** | 不做任何处理 | 颜色已经调好，只想加框 |
| **人像** | 降对比、抬阴影、压高光、微暖；锐度只有 4% | 肖像、合影、肤色要通透的场景 |
| **风光** | 清晰度 30%、饱和 118%、微冷、轻暗角 | 山川、草原、海边、建筑 |
| **夜景** | 高光 -34 保灯、阴影 +20 找回暗部、冷调、重暗角、颗粒 10% | 城市夜景、灯会、星空前景 |
| **黄昏** | 色温 +26 强暖、光晕 18%、中对比 | 日落、逆光、金色时刻 |
| **清新** | 提亮、降对比、轻褪色、轻光晕 | 日系写真、白墙、绿植、生活记录 |
| **电影** | 冷色温 + 洋红色调（青橙分离）、褪色 14% 抬黑位、暗角 | 叙事感、街拍、短片截帧 |
| **暗调** | 曝光 -20、高对比、压阴影、重暗角 32% | 情绪片、男性肖像、单点布光 |

**按风格**

| 预设 | 观感 | 适合 |
|---|---|---|
| **胶片** | 降饱和、轻微提亮、暖调、轻暗角、颗粒 26% | 日常、旅行、人文 |
| **复古** | 强棕调、褪色感、重暗角、颗粒 20% | 老街、旧物、年代感 |
| **黑白** | 全去色、加对比、轻暗角、颗粒 24%、清晰度 18% | 结构、光影、纪实 |
| **日系** | 亮、低对比、清淡、微微偏冷、轻光晕 | 逆光、室内、生活方式 |
| **柔光** | 低对比、整体提亮、光晕 26%、抬阴影 | 人像、浅色场景 |
| **浓郁** | 高饱和、高对比、清晰度 22%、锐度 14% | 色彩重的题材、旅行大景 |
| **冷调** | 明显偏蓝、加对比、清晰度 10% | 阴天、水面、清晨的城市 |

> 这些参数是按「业界通行做法」定的：人像压对比 + 抬阴影 + 收高光（皮肤才通透，
> 锐度必须低，否则毛孔和噪点会被强化）；风光靠清晰度撑通透、蓝绿加饱和；
> 夜景先保高光再提阴影，对比不能拉满（拉满会把这两件事全抵消，实测暗部反而更黑）。

**强度**（0–100%）在原图和预设之间线性插值：100% 是预设本来的样子，50% 是
「有点那个味道但不过分」，0% 等于关掉。选「原图」也可以完全关闭。

**微调**

预设下面有 **17 根滑杆**，分「影调 / 色彩 / 质感」三组，可以脱离预设自己调。
这个区块**默认是展开的**，点标题右侧的「收起」可以折起来只占一行。
只要动任意一根滑杆，预设会自动切成「自定义」，但数值保留。

*影调*

| 滑杆 | 范围 | 作用 |
|---|---|---|
| **曝光** | -100 – +100 | 整体乘除（`brightness`）。正数整体变亮，高光最先冲掉；负数变暗，黑位仍是黑 |
| **亮度** | 50% – 150% | 推中间调，比曝光温和，暗部不会死、高光不会爆 |
| **对比** | 50% – 150% | 明暗层次，超过 100% 更硬朗 |
| **高光** | -100 – +100 | 只动亮部。负数把快爆的高光拉回来，正数让亮部更亮 |
| **阴影** | -100 – +100 | 只动暗部。正数提亮暗部找回细节，负数压成剪影 |

**曝光和亮度有什么区别**：曝光是乘法，整幅画按比例缩放，亮部绝对值变化最大，
所以容易冲爆；亮度走中间调，暗部抬得少、亮部压得也少，整体更柔和。想「整体亮一档」
用曝光，想「稍微通透一点」用亮度。

*色彩*

| 滑杆 | 范围 | 作用 |
|---|---|---|
| **饱和** | 0% – 200% | 色彩浓度，0 就是全灰 |
| **色相** | -45° – 45° | 整体色相偏移，负值偏冷/偏紫 |
| **去色** | 0% – 100% | 抽掉颜色，100% 是全灰但保留层次 |
| **棕褐** | 0% – 100% | 叠加棕褐色调（对应 CSS 的 sepia） |
| **色温** | -100 – +100 | 负数偏冷（加蓝），正数偏暖（加橙），0 是原样 |
| **色调** | -100 – +100 | 负数偏青绿，正数偏洋红，用来修掉荧光灯下的偏色 |

*质感*

| 滑杆 | 范围 | 作用 |
|---|---|---|
| **清晰度** | 0% – 100% | 大半径局部对比，画面「更透、更结实」 |
| **锐度** | 0% – 100% | 小半径边缘强化，细节更利 |
| **光晕** | 0% – 100% | 高光溢出，太阳、灯、水面反光周围起一圈光 |
| **褪色** | 0% – 100% | 抬起黑位，暗部不再死黑，老照片那种发灰感 |
| **暗角** | 0% – 100% | 压暗四角，把视线收到画面中心 |
| **颗粒** | 0% – 100% | 胶片颗粒，详见 4.6 |

**清晰度和锐度有什么区别**：两者用的是同一套做法（叠一层模糊副本拉开对比），
区别只在半径——清晰度的半径是画面短边的 0.9%（2000px 输出约 18px），动的是
「块面之间的关系」；锐度的半径只有 0.22%（约 4px），动的是「边缘那一两个像素」。
前者让画面通透，后者让细节扎手。

> 这两个是近似实现：Canvas 2D 没有卷积，做不了真正的 USM（需要带符号的
> 高通，而 canvas 的混合模式做不了减法）。所以除了边缘对比，它们还会
> 附带一点点**整体对比**的提升——这跟修图软件里 clarity 的行为其实是一致的。

**棕褐和色温有什么区别**：棕褐是把整幅画往单一棕色调推（`sepia`），会明显吃掉原本的色彩；
色温只是把白平衡往暖或冷挪一点，颜色之间的关系保留。想要「旧照片」用棕褐，想要
「夕阳下的暖」用色温。

**和预设怎么配合**：点一个预设，它的数值会灌进这 17 根滑杆；你随便动一根，
就会自动切到「自定义」，其余 16 根保持预设的样子。所以最常见的用法是
「选个接近的预设 → 只调一两根」。

**和强度怎么配合**：强度是整体缩放，滑杆是逐项设定，两者相乘生效。
强度 100% + 饱和 140% = 饱和 140%；强度 50% + 饱和 140% ≈ 饱和 120%。
嫌两根旋钮重复的话，只用滑杆、强度留 100% 就行。

几个用法：

- 一组照片想统一风格 → 选一个预设，强度 100%
- 只想统一一点点 → 强度 40–60%，比全量套用自然得多
- 黑白 + 颗粒 40% = 直接出纪实感
- 荧光灯下拍的室内偏绿 → 色调往正数（洋红）推 20–30 就能拉回来
- 阴天灰蒙蒙 → 对比 +8、褪色 +10，比硬拉饱和自然
- 逆光人像脸发黑 → 阴影 +35、高光 -25，两头一拉就平衡了
- 老镜头拍的通透感 → 清晰度 30、锐度 15
- 柔焦 / 光影版式下，虚化的底图会跟主体一起调色，不会出现「主体暖、背景冷」的割裂
- 暗角在柔焦 / 光影这种「虚化底 + 主体卡」的版式里，是**整张画布只压一次**，
  主体卡上不会再多出一圈假暗角
- 清晰度 / 锐度 / 光晕在虚化底图上会跳过——底图本来就该糊

### 4.3 边缘模糊（仅柔焦版式）

| 参数 | 范围 | 说明 |
|---|---|---|
| **模糊强度** | 1% – 18% | 背景虚化程度 |
| **背景放大** | 100% – 180% | 底图放大倍数，防止虚化后四周露边 |
| **背景亮度** | 50% – 115% | 底图明暗，压暗可突出主体 |
| **主体大小** | 55% – 96% | 清晰主体占画面短边的比例，默认 90% |
| **边缘羽化** | 0% – 25% | 主体边缘的柔和过渡，默认 0，即硬边卡片 |
| **边缘阴影** | 0% – 100% | 主体下方的投影强度。调到 0 则完全浮在背景上 |

柔焦的层次是：虚化底 → 清晰主体 → 边缘羽化融入 → 阴影分离 → 底部文字。

默认的羽化是 **0**，出来是一张边缘干净、靠阴影浮在虚化底上的硬边卡片。
想要主体「逐渐失去焦点」融进背景，把羽化拉到 6%–12%；拉到 20% 以上会接近
无边界，适合纯情绪片。

### 4.4 底部文字（仅柔焦 / 光影）

| 参数 | 说明 |
|---|---|
| **第一行** | 默认 `{camera}`，渲染为「● 品牌机型」 |
| **第二行** | 默认 `{params}`，即拍摄参数 |
| **署名** | 底部第三行，字号等于副标，透明度 0.8（比副标稍淡） |
| **底图模糊 / 亮度** | 仅光影版式显示（柔焦用自己那组） |

规则：

- 两行都留空 → 只显示署名
- 第一行留空、第二行有内容 → 第二行自动提上来占第一行位置
- 两行都留空且没有署名 → 不占任何空间
- 没有 EXIF 的照片 → 两行自动消失，不留空行

### 4.5 文字

| 参数 | 说明 |
|---|---|
| **标题** | 全局标题，可被单张图的标题覆盖 |
| **信息模板** | 多行信息，用 `\|` 分行。空值自动省略 |
| **署名** | 光影/柔焦下是底部第三行；其他版式是信息区末尾一行 |

### 4.6 颗粒

颗粒在「调色 → 质感 → 颗粒」，一根 **0% – 100%** 的滑杆，0 就是关掉。

| 强度 | 观感 |
|---|---|
| 10–25% | 极细的质感，接近高感光底片的自然噪点 |
| 30–50% | 明显的胶片颗粒，大部分场景的甜点区 |
| 60% 以上 | 粗糙、颗粒感很强，适合故意的粗粝风格 |

颗粒只加在照片本身，边框和背景保持干净。柔焦版式下，颗粒会跟着**羽化边缘**
一起渐变，不会在主体边界切出一条直线。

因为它是调色参数的一员，所以：**预设会带上颗粒**（胶片 26%、黑白 24%、复古 20%、
暗调 12%、夜景 10%、电影 8%），**「强度」会一起缩放它**，动这根滑杆也会把当前预设切到「自定义」。

> 早期有过「全图 / 仅主体 / 主体以外」四档选择，后来又变成一个勾选框。
> 实际用下来，「全图」和「主体以外」都是整张画面糊一层噪点——尤其柔焦的底图
> 本来就是虚化的原图，两种模式几乎看不出区别，所以砍掉，只留主体颗粒。

### 4.7 配色

三个色：**底色**（卡纸/背景）、**文字**、**点缀色**（圆点、竖条、分隔线）。

每个都提供预设色板，也可以直接调色。

### 4.8 画幅与输出

| 参数 | 说明 |
|---|---|
| **比例** | 跟随原图 / 1:1 / 4:5 / 3:2 / 16:9 / 3:4 |
| **输出长边** | 1080 / 1600 / 2000 / 3000 / 4000 px / **原始尺寸** |

## 八、常见问题

**Q：为什么有些照片显示「无 EXIF 信息」？**

EXIF 解析只针对 **JPEG**。PNG、WebP 里没有相机元数据（或者格式不同），所以读不到。画面照常渲染，只是相机信息那几行会空着。

**Q：导出的图里有 EXIF 吗？**

没有。相机信息是**画进画面**的，文件本身的元数据是空的。这样在任何平台都不会因为元数据被剥离而丢失信息。

**Q：提示「已导出」，但找不到文件在哪？**

导出走的是浏览器下载，文件不会出现在页面里。先看下载记录：`Ctrl + J`（Chrome / Edge），
或者直接打开下载文件夹（默认 `C:\Users\你的用户名\Downloads`）。

如果下载列表里没有，或者显示「已阻止」，通常是这两种：

- **页面被嵌在别的应用的内置浏览器里**（某些预览面板、IDE 内置预览），下载会被
  静默拦掉，不报错。用 Chrome / Edge 直接打开页面就好。
- **Chrome 拦截 http 页面的 zip 下载**。用部署后的 `https://` 地址，或者本地双击
  打开，都不会有这个问题。

工具本身留了退路：导出后的提示条上挂着一个 **「手动保存」** 链接，停留 12 秒。
自动下载被拦时，点它可以直接把文件存下来。

**Q：为什么拖参数时画面不抖了？**

预览按屏幕实际像素固定渲染尺寸，画布盒子用 `aspect-ratio` 锁死，所以改参数不会触发页面重排。之前会抖是因为预览先出小图、停手再换大图，画布尺寸一变整页就跳。

**Q：支持 HEIC 吗？**

不支持。浏览器原生解码不了 HEIC。iPhone 可以在「设置 → 相机 → 格式」里改成「兼容性最佳」，或导出时选 JPEG。

**Q：支持 RAW 吗？**

支持 NEF / CR2 / CR3 / ARW / DNG / RAF / ORF / RW2 等，但用的是**相机内嵌的 JPEG 预览**，不是 RAW 解出来的像素——原理和代价见第十节。卡片上会标 `RAW` 和预览的实际像素，一眼能看出够不够用。

**Q：参数会保存吗？**

点「我的预设 → 保存当前样式」（或 `Ctrl/⌘ S`），存在本机浏览器里，下次打开自动恢复。换电脑或清缓存就没了。

**Q：怎么把样式发给别人？**

「导出参数」会下载一个 `光影相框_样式_20261026.json`，对方点「导入参数」选中它就能还原。导入时会做校验：不认识的字段、类型不对的值、超出范围的数字（比如 `padding: 999`）都会被丢掉或夹到边界，不会把界面搞坏。

**Q：为什么有张照片显示「无法解码」？**

浏览器原生解码不了这个格式（常见是 HEIC、改了后缀名的非图片文件、或者文件本身损坏）。这张卡片会标红、自动取消勾选，不会计入导出数量，其余照片照常处理。转成 JPEG 后重新拖进来即可。

**Q：能批量处理整个文件夹吗？**

现在只能手动拖。如果你需要命令行批处理版本，可以说一声。

**Q：一次能处理多少张？**

没有硬限制，但几十张以上建议分批，避免浏览器内存吃紧。2000px 单张渲染约 1–4ms，主要开销在解码大图。读取 EXIF 时只读文件前 256KB（相机信息就在开头），不会为了 2KB 元数据把整张图读进内存。

## 九、实现说明

给好奇的人。

**零依赖**：没有 CDN、没有 npm 包、没有字体文件，断网可用。所有逻辑在一个 HTML 里，分三段脚本：

```
CORE      纯逻辑：EXIF 解析、CRC32、ZIP 打包、token 展开、机身名清洗
渲染引擎    Canvas 2D：8 个版式的绘制、羽化、颗粒、文字排版
应用层     DOM：状态管理、事件绑定、导出流程
```

**EXIF 解析**是手写的：JPEG APP1 段 → TIFF 头（大小端兼容）→ IFD 遍历 → Exif 子 IFD，按 tag 取机身、镜头、光圈、快门、ISO、焦距、日期。

**ZIP 打包**也是手写的：CRC32 查表 + store-only（不压缩）结构。照片本身已是压缩格式，再压意义不大，直接存能省 CPU。

**边缘羽化**用 `destination-in` 配合四边线性渐变，缓入曲线 `0 → 0.22 → 0.72 → 1`，避免两段式渐变的生硬感。

**渐进失焦**：清晰层下面垫一层同亮度、同位置的虚化层，边缘不是「淡出成背景」而是「逐渐失去焦点」，观感更接近真实镜头。

**颗粒**用 128×128 的噪点贴图平铺，按画面短边缩放（2000px 输出约 2.6px 一颗），`overlay` 混合模式叠加，裁剪到照片主体的圆角路径内。柔焦版式下改用羽化蒙版的 `destination-in`，边界会跟着羽化一起渐变。

**调色**分四条通道，都不做逐像素循环（颗粒除外，它是平铺一张噪点贴图），
所以 4000px 导出也不会明显变慢。每条通道为空时整条跳过，默认参数下零开销。

第一条是 **CSS 滤镜**：亮度 / 对比 / 饱和 / 色相 / 去色 / 棕褐这六项，正好是
`ctx.filter` 能表达的，就把预设拼成一串 CSS 滤镜（contrast / saturate / sepia /
grayscale / brightness / hue-rotate），在 `drawCover` 这一个入口统一接上。所有照片绘制
（主体、柔焦的虚化底、羽化蒙版）都经过 `drawCover`，所以只接一次就够，也不会重复叠加。
虚化底图本来带着 `blur()`，调色滤镜直接拼在它后面。曝光也走这条路，但用
`brightness(2^(ev/100))` 并**强制排在最前面**——先整体缩放，后面的对比和饱和才作用在
已经缩放过的画面上。

第二条是 **叠色**：亮度 / 高光 / 阴影 / 色温 / 色调 / 褪色 / 暗角这七项 `ctx.filter`
表达不了，改成照片画上去之后，在同一个矩形里再盖一层带混合模式的颜色——亮度用
`soft-light` 推中间调，高光负数用 `multiply`、阴影正数用 `screen`（只吃一端），
色温和色调用 `soft-light`（橙 / 蓝、洋红 / 青绿），褪色用 `screen` 抬黑位，
暗角是椭圆径向渐变。因为调用点同样在 `drawCover` 里，叠色和照片矩形严丝合缝，
绝不会盖到卡纸上。`buildGradeFilter` 有一份 `CSS_FILTER_KEYS` 白名单，
叠色参数不会被误写进滤镜字符串（写进去整串滤镜都会失效，而且是静默失效）。

第三条是 **质感**：清晰度 / 锐度 / 光晕都是「把照片自己模糊一份，再用混合模式叠回去」，
区别只在模糊半径和混合模式（前两个 `overlay`，光晕 `screen`）。光晕在模糊前先套一层
`contrast(1.7)` 当**软阈值**，把暗部压向 0——否则 `screen` 会把整幅画面的暗部一起抬起来，
整张发灰（这是早期的真实 bug）。

第四条是 **颗粒**：128×128 的灰度噪点平铺，按画布尺寸放大，`overlay` 混合。

强度是在「恒等值」和「预设值」之间线性插值（比如 contrast 从 1.0 插到 0.94，色温从 0 插到 14），
所以拉到 0% 时整串滤镜为空、叠色全为 0，等于零开销，不会比不调色更慢。

**暗角为什么不跟照片矩形走**：柔焦和光影是「虚化底 + 主体卡」两层，如果每层各压一次暗角，
主体卡上会多出一圈和画框无关的假暗角。所以这两层调用 `drawCover` 时传 `noVignette`，
最后在整张画布上统一补一次。

## 十、RAW 文件

浏览器解不了 RAW 的像素数据，这个工具也没打算塞一个几 MB 的 WASM 解码器——那样就不能「双击即用、断网可用」了。

它的做法是：**把相机存在 RAW 里的那张 JPEG 预览取出来用**，同时从 RAW 的 TIFF 结构里读 EXIF。

### 支持的格式

| 扩展名 | 相机 |
|---|---|
| `.nef` `.nrw` | 尼康 |
| `.cr2` `.cr3` | 佳能 |
| `.arw` `.srf` `.sr2` | 索尼 |
| `.dng` | Adobe / 徕卡 / 多数无人机 |
| `.raf` | 富士 |
| `.orf` | 奥林巴斯 |
| `.rw2` `.raw` | 松下 |
| `.pef` | 宾得 |
| `.srw` | 三星 |
| `.3fr` | 哈苏 |
| `.iiq` `.mrw` `.x3f` `.erf` `.kdc` `.dcr` `.rwl` | 其他 |

判定靠扩展名，不看 MIME——RAW 文件的 MIME 通常是空的，所以拖进来时浏览器不给 `image/*`。

EXIF 的读法分两路：TIFF 容器（NEF / CR2 / ARW / DNG / ORF / RW2…）直接读文件头的 IFD；CR3 是 ISO BMFF，要去 `CMT1` / `CMT2` box 里找。CR3 这条路是尽力而为，读不到时卡片只显示预览尺寸，图照样能出。

### 它怎么找到预览图

扫整个容器，找出所有**结构完整**的 JPEG 段（`FF D8` 起，逐段校验 marker 长度，`FF D9` 止），取字节最大的那张。

- 大多数相机在 RAW 里同时存缩略图和全尺寸/中尺寸预览，取最大就是主预览
- 不依赖厂商的 IFD 指针（CR2 / ARW / NEF 的布局各不相同），一份代码通吃
- 40MB 的容器扫一遍约 60ms，EXIF 解析基本 0ms

### 代价：预览分辨率通常低于传感器

卡片上会写明实际能用多少像素：

```
DSC_0001.NEF  [RAW]
NIKON Z5_2 · 预览 1620×1080 · 45mm · f/2.8 · 1/60s · ISO800
```

`1620×1080` 才是你能导出的上限；`{size}` token 给的是 `6000×4000`，那是传感器真实尺寸。

所以 **RAW 适合出社交平台的图，不适合印刷级大图**。要最高画质，先用相机厂商软件或 Lightroom 导出 JPEG/TIFF 再拖进来。

### 抽不到预览会怎样

少数情况会失败：有的 DNG 只存裸数据、机身设置里关掉了预览、文件损坏。这张会标红显示「RAW 无内嵌预览」并自动跳过，不影响其他照片。

### 内存

RAW 单张 30–60MB，十张一起读会把内存吃穿。所以 RAW 是**串行处理**的——读完一张、抽出预览、释放容器，再读下一张。普通 JPEG / PNG 仍然是并行的。

## 十一、已知限制

- **只读 JPEG 的 EXIF**，PNG/WebP 无相机信息（RAW 走 TIFF 结构，能读）
- **不支持 HEIC**（浏览器解码限制）
- **RAW 用的是内嵌 JPEG 预览**，分辨率通常低于传感器；抽不到预览的 RAW 会被跳过
- **导出无元数据**（信息已烧录进画面）
- **原始尺寸上限 12000px 长边**，超出会按 12000 处理，防止 canvas 内存溢出
- **ZIP 不压缩**，体积约等于所有成品图之和
- **文字超量自动缩字 / 丢行**，不会溢出画布，但也意味着超长文本会被截断而不是换行
- **侧栏很长**：微调默认展开，17 根滑杆 + 15 个预设让侧栏约 3200px 高，改版式参数要滚动
- 参数预设存在 localStorage，换浏览器/清缓存会丢

| 需要什么 | 说明 |
|---|---|
| Cloudflare 账号 | 免费注册，不用绑卡。没有的话先去 dash.cloudflare.com 注册 |
| Node.js 18+ | 本机已装 v22.22.2，`node --version` 能出版本号就行 |
| 终端 | Windows 用 PowerShell 或 Git Bash 都行 |

Wrangler（Cloudflare 的命令行工具）不需要单独安装，`npx` 会在第一次运行时

### 13.2 第一次部署：五步

**第 1 步 · 进项目目录**

```bash
cd C:\Users\17265\Desktop\demo
```

后面所有命令都在这个目录下执行。目录里必须有 `wrangler.toml`，否则 wrangler
不知道要部署什么。

**第 2 步 · 构建**

```bash
node build.mjs
```

期望输出：

✓ dist\index.html  126 KB  外链 0 个

两行都对才算构建成功。如果第一行报「发现外部资源引用」，说明源 HTML 里混进了

5. 终端出现 `Successfully logged in.` 就成功了

以后不用重复登。想确认当前登录状态：

```bash

```

会列出账号邮箱和 Account ID。

> 如果浏览器没自动打开，终端里会打印一个 `https://dash.cloudflare.com/oauth2/auth?...`
> 的长链接，复制到浏览器手动打开即可。

**第 4 步 · 部署**

```bash
npx wrangler deploy
```

期望输出（节选）：

```
✨ Read 2 files from the assets directory C:\Users\17265\Desktop\demo\dist
Uploaded guangying-frame (1.23 sec)
Deployed guangying-frame triggers (0.45 sec)
  https://guangying-frame.<你的子域>.workers.dev
```

最后那行 URL 就是线上地址，点开就能用。**第一次部署可能会多问一句**：要不要
注册一个 `workers.dev` 子域——选 `y`，那个 `<你的子域>` 是你自己起的名字，
全局唯一，起完以后所有 Worker 共用它。

**第 5 步 · 验证**

打开 URL，然后确认三件事：

1. **页面能出来**——标题是「光影相框 · 批量加框工作台」
2. **功能正常**——拖一张 JPG 进去，右侧应该出预览图，左侧改参数实时重绘
3. **安全头生效**——在终端里：

```bash
curl -I https://guangying-frame.<你的子域>.workers.dev
```

响应头里应该能看到 `content-security-policy`、`x-content-type-options`、
`referrer-policy` 这几行。有，说明 `_headers` 被正确读取了。

> 如果第 1、2 步正常但第 3 步没有安全头，就是 `dist/_headers` 没上传上去。
> 重跑一次 `node build.mjs && npx wrangler deploy`。

### 13.3 以后更新

改完 `光影相框.html`，两条命令搞定：

```bash
node build.mjs && npx wrangler deploy
```

十几秒完成，URL 不变。不需要重新登录。

### 13.4 本地预览线上环境

```bash
npx wrangler dev
```

会起一个 `http://localhost:8787` 的本地服务，跑的是真正的 Worker 运行时。

和「双击打开 HTML」的区别：只有 `wrangler dev` 会让 `_headers` 里的 CSP 真实生效。
**改了安全头一定要跑一次**——CSP 写错的表现是页面能加载但功能全死，双击打开
是测不出来的。

### 13.5 绑定自定义域名（可选）

想要 `frame.你的域名.com` 这种地址，需要两步：

**第一步：把域名接入 Cloudflare**（已有域名可跳过）

在 Cloudflare 控制台「添加站点」→ 输入域名 → 选免费套餐 → 它会给你两个 NS
地址 → 去域名注册商那里把 NS 改成这两个 → 等生效（几分钟到几小时）。

**第二步：改配置再部署**

打开 `wrangler.toml`，把底部这段的注释去掉，域名换成你的：

```toml
[[routes]]
pattern = "frame.你的域名.com"
custom_domain = true
```

然后重新部署：

```bash
npx wrangler deploy
```

Cloudflare 会自动签发证书，几分钟后域名就能访问。`custom_domain = true` 的
好处是不用手动建 DNS 记录，Cloudflare 自己会加。

### 13.6 出问题了怎么查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `npx wrangler` 卡在下载不动 | 网络问题 | 换网络重试；或先 `npm i -D wrangler` 装到项目里 |
| `You are not authenticated` | 没登录或凭证失效 | 重新 `npx wrangler login` |
| 浏览器授权后终端一直转圈 | 代理拦了 `localhost:8976` 回调 | 临时清代理：PowerShell 用 `$env:HTTP_PROXY=''`、`$env:HTTPS_PROXY=''`；Git Bash 用 `unset HTTP_PROXY HTTPS_PROXY`，然后重试 |
| `Authentication error [code: 10000]` | 账号权限或 token 过期 | 重新登录；确认账号已激活 |
| 部署成功但打开是 404 | `dist/` 里没有 `index.html` | 重跑 `node build.mjs`，确认 `dist` 里有两个文件 |
| 页面能开但按钮全没反应 | CSP 太严，脚本被拦 | `npx wrangler dev` 看控制台报错，放宽 `_headers` 里的 `script-src` |
| 改了代码线上没变 | 浏览器缓存 | `Ctrl + F5` 强刷；或换隐身窗口 |
| 部署报 `name` 冲突 | 该名字已被别的账号占用 | 改 `wrangler.toml` 里的 `name` |

### 13.7 不想注册账号先看看效果？

Wrangler 支持临时部署，不用登录：

```bash
npx wrangler deploy --temporary
```

会给一个临时 URL，**有效期 60 分钟**，同时打印一个 Claim 链接——访问那个链接
可以把这次部署认领到自己的正式账号下，否则到期自动销毁。适合「先给朋友看一眼」。

### 13.8 免费额度

Workers 免费版每天 10 万次请求（静态资源请求也计入）。这个工具是纯前端单页，
一次访问只产生 1 个请求，个人分享完全够用。超出后当天停服，次日恢复，不会扣费。

## 十四、另一条路：不装命令行，直接粘贴到控制台

### 14.1 什么时候用这条

不想装 Node 环境、不想跑 `wrangler login`、只想快点拿到一个能分享的链接——
就用这条。全程在浏览器里完成，不碰终端。

代价只有一个：**每次更新要手动重新粘贴一次**，没有「一条命令搞定」。

### 14.2 先生成粘贴文件

```bash
node build-worker.mjs
```

期望输出：

```
✓ worker.js  127 KB（源 HTML 126 KB，已内联）
```

它做的事：把整个 HTML 转成一个 JS 模板字符串，塞进一个直接返回 `Response`
的 Worker 脚本里。所以粘贴一个文件就够了，不需要上传任何静态资源。

> 脚本大小 127 KB，Cloudflare 免费版脚本上限是 3 MB，余量很大。

### 14.3 控制台五步

1. 打开 `dash.cloudflare.com`，左侧栏点 **Workers & Pages**
2. 右上角 **Create** → 选 **Workers** 标签 → **Get started**（Hello World 模板）
3. 起个名字（比如 `guangying-frame`）→ 点 **Deploy**
4. 进到 Worker 详情页，点右上 **Edit code** 打开在线编辑器
   → 编辑器里 `Ctrl + A` 全选 → 删除 → 把 `worker.js` 的全部内容粘进去
5. 右上角 **Deploy**，等几秒

地址就是 `https://<你起的名字>.<你的子域>.workers.dev`。

> 判断格式对不对：默认模板里应该能看到 `export default {`，这是 ES Module 格式，
> 我们的代码可以直接整段替换。如果你看到的是 `addEventListener('fetch', ...)`，
> 那是旧版 Service Worker 格式，**先把编辑器清空再粘贴**，别两种混在一起。

### 14.4 验证

同 13.2 第 5 步：页面能开、拖张图能出预览、`curl -I` 能看到
`content-security-policy`。

粘贴版的响应头写在脚本里的 `HEADERS` 常量里，所以 `curl -I` 一定查得到；
查不到就说明粘贴没成功或者没点 Deploy。

### 14.5 两条路线怎么选

| | wrangler 部署（第十三节） | 控制台粘贴（本节） |
|---|---|---|
| 需要装 Node | 要（本机已有 v22） | 不用 |
| 首次要终端登录授权 | 要 | 不用，网页已登录 |
| 更新一次 | 一条命令，十几秒 | 重新生成 + 手动粘贴 |
| 安全头来自哪里 | `_headers` 文件 | 脚本里的 `HEADERS` 常量 |
| 自定义域名 | 改 `wrangler.toml` | 控制台里点 |
| 适合 | 长期维护、频繁改 | 快速上线、换电脑演示 |

### 14.6 别两条路混用

两条路写的是**同一个 Worker 名字**。如果你先用粘贴版上线，之后又在本地跑
`npx wrangler deploy`，会把这个 Worker 覆盖成「纯静态资源」版本，粘贴进去的
脚本就没了——反过来也一样。

选一条固定用。改了 `光影相框.html` 之后：

- 走第十三节 → `node build.mjs && npx wrangler deploy`
- 走本节 → `node build-worker.mjs`，然后重新复制粘贴
